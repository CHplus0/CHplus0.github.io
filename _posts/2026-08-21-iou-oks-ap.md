读一篇动物姿态估计的数据集论文时，我发现表格里全是 AP、mAP、OKS，却说不清这些数字是怎么来的。这篇笔记按我当时的学习顺序，从最基础的 IoU 讲起，一直到论文表格里的 AP。

文中的数值例子都是构造出来的小矩阵，可以直接复制运行。

## IoU 是什么？

IoU（Intersection over Union，交并比）衡量两个区域的重合程度：

$$
\text{IoU}(A, B) = \frac{|A \cap B|}{|A \cup B|}
$$

取值范围是 0 到 1。完全不重叠为 0，完全重合为 1。

**为什么分母用并集，而不是其中一个区域的面积？** 假设分母只用真值区域的面积，那么预测画得越大越好：画一个巨大的框把真值整个包住，就能拿满分。用并集做分母后，多画（并集变大）和少画（交集变小）都会被惩罚。

检测任务里常用的刻度：0.5 算「基本对上」，0.75 算「相当准」，0.9 以上接近完美。

## 预测比真值大了一圈，IoU 会是多少？

先猜一下：分割结果比动物大了一圈，但完全包住了动物，IoU 大概是多少？

我当时的猜测是「一定小于 1，而且大概在 0.5 以上」。前半句是对的，后半句需要具体算一算。

当预测 $$P$$ 完全包含真值 $$T$$ 时，交集就是 $$T$$ 本身，公式退化成面积比：

$$
\text{IoU} = \frac{|T|}{|P|}
$$

用 numpy 在小格子上验证：

```python
import numpy as np

a  = np.zeros((7, 7), bool); a[2:5, 2:5]  = True   # 真值：3×3，9 格
b1 = np.zeros((7, 7), bool); b1[1:5, 1:5] = True   # 4×4，完全包住 a
b2 = np.zeros((7, 7), bool); b2[0:5, 0:5] = True   # 5×5，完全包住 a

iou = lambda x, y: (x & y).sum() / (x | y).sum()
print(iou(a, b1))   # 0.5625 = 9/16
print(iou(a, b2))   # 0.36   = 9/25
```

边长只多了一两格，IoU 就从 1 掉到了 0.56 和 0.36。原因是**面积随边长平方增长**。如果预测把真值的宽和高都放大到原来的 $$(1 + k)$$ 倍并完全包住它，那么

$$
\text{IoU} = \frac{1}{(1 + k)^2}
$$

所以「大一圈」到底有多严重，取决于这一圈**相对于物体有多大**：

- 200×200 px 的大型动物，四周各多 10 px：边长变成 220，$$k = 0.1$$，IoU ≈ 0.83。
- 20×20 px 的小动物，同样四周各多 10 px：边长变成 40，$$k = 1$$，IoU = 0.25。

同样的绝对误差，在小物体上是严重错误，在大物体上只是毛边。这个「需要按物体尺寸归一化」的想法，正是后面 OKS 要解决的问题。

在讲 OKS 之前，需要先弄清楚论文和代码里通用的 COCO 格式。

## COCO 是什么？

COCO（Common Objects in Context）是微软在 2014 年发布的图像数据集，覆盖检测、实例分割、关键点等任务。它的影响力远不止数据本身，更在于它同时定义了三样东西：

1. 一个公共基准，大家的结果可以直接比较；
2. 一套评测指标，包括检测和分割的 AP，以及关键点的 OKS 和 AP；
3. 一种 JSON 标注格式，后来大量姿态数据集都沿用它。

关键点任务的标注大致长这样：

```json
{
  "images":      [{"id": 1, "file_name": "xxx.jpg", "width": 1920, "height": 1080}],
  "annotations": [{"id": 1, "image_id": 1, "category_id": 1,
                   "bbox": [x, y, w, h],
                   "keypoints": [x0, y0, v0, x1, y1, v1, "..."],
                   "num_keypoints": 15}],
  "categories":  [{"id": 1, "name": "animal", "keypoints": ["left_eye", "..."]}]
}
```

有三个约定值得记住。

**bbox 是 `[x, y, w, h]`**，即左上角坐标加宽和高，而不是两个对角点。比如 `[847, 200, 192, 143]` 的右下角是 $$(847+192,\ 200+143) = (1039, 343)$$。

**keypoints 按点交错排列**，每 3 个数描述一个点：

```text
[x0, y0, v0,  x1, y1, v1,  ...,  x(K-1), y(K-1), v(K-1)]
 └─ 点 0 ─┘   └─ 点 1 ─┘         └──── 点 K-1 ────┘
```

所以 $$K$$ 个关键点对应 $$3K$$ 个数，第 $$i$$ 个点就是 `kps[3*i : 3*i+3]`。`v` 是可见性标志：0 表示未标注，1 表示标注了但被遮挡，2 表示标注且可见。

**id 是全局唯一的**。annotation 通过 `image_id` 关联到图片。

{% details ❌ 常见误解：annotations[0] 就是「第一张图里的第一只动物」 %}

不一定。`annotations` 只是一个扁平列表，第 0 条可能属于任何一张图、任何一个类别。想知道它是哪张图，要用 `image_id` 去 `images` 里查。

```python
a = d["annotations"][0]
img = next(i for i in d["images"] if i["id"] == a["image_id"])
points = [a["keypoints"][i:i+3] for i in range(0, len(a["keypoints"]), 3)]
```

{% enddetails %}

## OKS：怎么给「关键点偏了多少」打分？

IoU 比较的是两个区域，而关键点是一个个点，需要另一把尺子。OKS（Object Keypoint Similarity）的作用相当于关键点版的 IoU。COCO 的定义是：

$$
\text{OKS} = \frac{\sum_i \exp\!\left(-\dfrac{d_i^2}{2\, s^2 \kappa_i^2}\right)\, \delta(v_i > 0)}{\sum_i \delta(v_i > 0)}
$$

其中：

- $$d_i$$：第 $$i$$ 个关键点预测位置和真值之间的欧氏距离；
- $$s^2$$：目标的面积（COCO 用的是分割区域的面积），$$s$$ 起到尺度归一化的作用；
- $$\kappa_i = 2\sigma_i$$：第 $$i$$ 类关键点的容差常数；
- $$\delta(v_i > 0)$$：只统计真值里标注过的点。

每个点的得分是一个高斯核，完全重合时为 1，偏得越远越接近 0。OKS 是这些得分在标注点上的平均。

**$$s$$ 管的是「这只动物有多大」。** 去掉 $$s$$ 会怎样？同样偏了 10 px，对大个体本来是很小的误差，却会被当成和小个体一样严重。结果是大个体被冤枉，小个体被放过，两个方向一起歪。

**$$\sigma_i$$ 管的是「这类点本身有多难标」。** COCO 在人体关键点上让多名标注者重复标注同一批图，按每类点的标注离散程度统计出 $$\sigma$$：

- 眼睛这类位置明确的点，大家标得很一致，$$\sigma$$ 小，要求严；
- 髋部这类隔着衣服、位置模糊的点，$$\sigma$$ 大，容忍度高。

用一个最小例子跑一遍。这里为了好算，令 $$s^2 = 100$$、$$\kappa = 0.1$$：

```python
import numpy as np

gt    = np.array([[10, 10], [20, 10]])
pred  = np.array([[11, 12], [20, 10]])   # 点 1 偏了 (1, 2)，点 2 完全重合
kappa = np.array([0.1, 0.1])
area  = 100.0                            # s² = 100

d2  = ((gt - pred) ** 2).sum(axis=1)     # [5, 0]
oks = np.exp(-d2 / (2 * area * kappa ** 2)).mean()
print(oks)   # ≈ 0.541：点 1 得 e^-2.5 ≈ 0.082，点 2 得 1
```

{% details ❌ 常见误解：容差大，要求就严 %}

方向是反的。$$\kappa_i$$（即 $$2\sigma_i$$）在分母里：$$\sigma$$ 越大，同样的距离扣分越少，要求越**松**；$$\sigma$$ 越小越严。

这个方向在讨论一个问题时很关键：如果某个数据集没有逐点统计标注方差，而是给所有关键点用同一个 $$\sigma$$，会发生什么？

- 原本 $$\sigma$$ 很小的点（比如眼睛）被**放宽**了；
- 原本 $$\sigma$$ 很大、难以精确标注的点被**卡严**了。

统一 $$\sigma$$ 的实际效果是抹平了点与点之间的难度差异。读论文时，值得留意它的 $$\sigma$$ 是怎么设的。

顺带一提，这个指标叫 OKS（Object **Keypoint** Similarity），不是 OKP。

{% enddetails %}

有了单个实例的 OKS，下一步是把它汇总成整个测试集上的一个分数。

## 从 OKS 到 AP：论文里的数字是怎么组装出来的？

这一步分三层。

**第一层：precision 和 recall。** 举个例子：图里有 10 只动物，模型给出 5 个预测，其中 4 个正确。

- precision = 4/5 = 0.8：模型说的话有多可信；
- recall = 4/10 = 0.4：该找到的找到了多少。

两个数缺一不可。

**第二层：在给定阈值 τ 下画 PR 曲线。** 每个预测都有一个**置信度分数**，这是模型自己给出的「我有多确定」。计算步骤如下：

1. 把所有预测按置信度从高到低排序；
2. 依次和尚未被匹配的真值配对。OKS ≥ τ 记为 TP，否则记为 FP；
3. 每处理一个预测，就记录一次累计的 (recall, precision)；
4. 把这些点连成 PR 曲线，曲线下的面积就是 $$\text{AP}_\tau$$。COCO 的实现会先对 precision 做「向右取最大值」的插值，再在 101 个 recall 点上取平均。

**第三层：对多个阈值求平均。** COCO 的主指标 AP 是 τ 取 0.50, 0.55, …, 0.95 共 10 档的 $$\text{AP}_\tau$$ 的平均值，同时单独报告 AP50 和 AP75。

注意：不同论文对「AP」和「mAP」的命名并不统一。有的把 AP50 叫 AP、把 10 档平均叫 mAP。读表格之前要先找到论文对指标的定义。

{% details ❌ 常见误解：按 OKS 从高到低排序来画 PR 曲线 %}

我学的时候做过一道练习，是把预测**按 OKS 排序**再累计。这样排的话，所有 TP 一定排在 FP 前面，precision 永远是先保持 1 再下降，曲线被画得过于乐观。

真实评测**按模型的置信度排序**。OKS 只用来判定每个预测是 TP 还是 FP。AP 衡量的其中一件事，正是「模型给高分的预测是否真的更准」。

一个对比例子：6 个真值，6 个预测，τ = 0.5。

| 置信度排名 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| OKS | 0.90 | 0.30 | 0.82 | 0.70 | 0.12 | 0.55 |
| 判定 | TP | FP | TP | TP | FP | TP |
| precision | 1.00 | 0.50 | 0.67 | 0.75 | 0.60 | 0.67 |
| recall | 1/6 | 1/6 | 2/6 | 3/6 | 3/6 | 4/6 |

先对 precision 做插值，即每个位置取它右侧的最大值。在 recall 为 1/6、2/6、3/6、4/6 处，插值后的 precision 分别是 1、0.75、0.75、0.67，因此

$$
\text{AP}_{0.5} \approx \tfrac{1}{6}(1 + 0.75 + 0.75 + 0.67) \approx 0.53
$$

如果按 OKS 排序，4 个 TP 全排在前面，会得到 4/6 ≈ 0.67。两者的差距，就是「置信度排序不够好」被扣掉的分数。另外，recall 最多到 4/6，因为有两个真值始终没有被任何预测以 OKS ≥ 0.5 覆盖。

{% enddetails %}

一句话总结这条链：**IoU 和 OKS 是尺子，AP 是成绩单。** 检测和分割任务用 IoU 判断命中，关键点任务用 OKS 判断命中，后面的 AP 组装流程是同一套。

## 这些指标到底在拿谁和谁比？

学到这里我产生了一个疑问：项目里的「真值」本身也是模型生成后再人工检查的，那 IoU 和 OKS 比的到底是什么？

关键在于区分两个阶段。

**阶段一：生产数据集。** 关键点由人工标注；分割掩码之类的辅助标注可能由模型先生成候选，再经过人工核查才转为真值。这个阶段的工作是**检查数据集本身的质量**，并不涉及训练任何姿态模型。

**阶段二：用数据集评测模型。** 训练好的姿态估计模型在测试集上做预测，用 OKS 和真值比较，汇总成 AP。论文表格里的数字基本都来自这个阶段。

同一个公式，因此可能出现在三个不同的场合：

| 比较 | 谁和谁比 | 目的 |
|---|---|---|
| 方案对比 | 新方案生成的掩码 vs 旧方案生成的掩码 | 看差异有多大，挑方案，不是打分 |
| 质量核查 | 候选标注 vs 图上真实的动物 | 决定候选能否转为真值 |
| 模型评测 | 模型预测 vs 真值 | 打分，即论文里的 AP |

两个阶段也有关联。数据集论文里的模型评测分数，常被**间接**当作标注质量的证据：如果标注很差，很难训练出高分模型。而人工核查得出的错误率，是对数据质量更**直接**的测量。

## 这个数据集最终在训练什么？

以 2D 动物姿态估计为例，最常见的是 **top-down** 流程：

1. 检测器先找出图里的每只动物，给出 bbox；
2. 按 bbox 裁出单只动物的图像；
3. 关键点模型对裁剪图输出 $$K$$ 个关键点。常见做法是对每个关键点输出一张热力图，取峰值位置作为坐标；
4. 把坐标映射回原图。

所以模型的输入是图像（加上框），输出是每只动物的 $$K$$ 个关键点坐标。很多论文在报告关键点精度时会直接用真值 bbox 裁图，这样就绕开了检测这一步。读论文时要注意这一点：这类数字衡量的是「框给定的情况下关键点定得准不准」，不是完整的端到端能力。

## 自测题

1. 两个 2×2 的正方形，A 占 [0, 2]×[0, 2]，B 占 [1, 3]×[1, 3]。IoU 是多少？

{% details 参考答案 %}
交集是 1×1 = 1，并集是 4 + 4 − 1 = 7，所以 IoU = 1/7 ≈ 0.143。
{% enddetails %}

2. 对比新旧两套掩码方案，得到 IoU = 0.8。这个值是高好还是低好？

{% details 参考答案 %}
取决于目的。方案对比里没有「正确答案」，IoU 只表示差异大小。如果想确认新方案没有带来实质性变化，0.8 说明还有不小的差异；如果是想找出需要人工复查的样本，就应该优先看 IoU 低的那些。
{% enddetails %}

3. 为什么 OKS 要除以目标尺度 $$s$$？去掉它，谁吃亏？

{% details 参考答案 %}
因为像素误差的严重程度和目标大小有关。去掉 $$s$$ 后，同样的像素偏移对大个体被扣成大错，大个体被冤枉；小个体本该被重罚的偏移反而被放过。
{% enddetails %}
